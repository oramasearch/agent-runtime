# agent-runtime v0.3.0

**Released 2026-11-16. A minor release.** The runtime's licence and open-source preparation, the
bus consumer and conversation memory bounded, and the image's bases pinned by digest, since
[v0.2.0](v0.2.0.md). The bounded bus and memory change behaviour a caller can see and add settings,
which is why this is a minor release and not a patch. Image: `docker.io/oramasearch/agent-runtime:v0.3.0`.

This release is the tree of `dev` after #39 (`f7e38b7`), with these notes and the version.

### The licence — #39

agent-runtime is released under the MIT licence, copyright OramaSearch, Inc. (`LICENSE`,
`COPYRIGHT`). Every source file carries `SPDX-License-Identifier: MIT`, added and checked by
`tools/spdx-headers.py`. `THIRD_PARTY_LICENSES` lists the licence of every dependency. Contributions
are made under `CLA.md` (contributors assign copyright to OramaSearch, Inc.), following
`CONTRIBUTING.md` and `CODE_OF_CONDUCT.md`. `tools/sbom.py` writes the software bill of materials in
SPDX 2.3 and CycloneDX, regenerated for this release.

### A security policy — #34

`SECURITY.md` says how to report a vulnerability privately and what we commit to in reply.

### The bus consumer and the conversation memory are bounded — #33

- **The bus consumer claims a task only when a worker is free to run it.** Nothing is received
  while every worker is busy, so claimed tasks (and their credentials) no longer pile up in memory,
  and a task left unclaimed stays on the bus for another replica. `AGENT_BUS_WORKERS` (default 4)
  run at once; one customer holds at most `AGENT_BUS_TENANT_WORKERS` (default one fewer), so one
  tenant's burst cannot take every worker. At most 256 dispatch rows wait.
- **Every bus turn carries Lake's claim** (`task_id`, `customer_id`, `workspace_id`) as `claim`.
- **Conversation memory is bounded.** At most `AGENT_CONVERSATIONS` conversations (default 256),
  each at most `AGENT_CONVERSATION_TURNS` turns (20) and `AGENT_CONVERSATION_BYTES` (1 MiB), all of
  them at most `AGENT_CONVERSATIONS_BYTES` (64 MiB); one idle for `AGENT_CONVERSATION_IDLE_SECONDS`
  (3600) is dropped.
- **A bus turn continues only the conversation its `prior_turn` left in the same account and
  workspace**, never one named by a caller's `conversation_id`. A direct `POST /v1/turn` keeps its
  own `conversation_id` key in a separate namespace, so it cannot reach a bus turn's history. A turn
  that raises is rolled back.

### The image's bases are pinned by digest — #35

Each `FROM` and `COPY --from` names the multi-platform index digest its tag pointed to, so a later
build of the same source gets the same base. A new base is a reviewed change of the digest.

### Prepared for a public export — #37

Links to issues and pull requests, internal names and wording are removed from the README, the docs
and the earlier release notes. The agent files (`CLAUDE.md`) ship with the repository.

## Behaviour changes to know before it rolls

1. **A bus turn's history is keyed by Lake's claim**, not by the `conversation_id` in its body. A
   bus caller that relied on naming a conversation to continue it continues only the chain its
   `prior_turn` names.
2. **Conversations are forgotten** past the limits above, oldest or idle first.
3. **The bus consumer runs at most `AGENT_BUS_WORKERS` turns at once** and leaves the rest on the
   bus.

## Settings it needs

No setting is required. Seven optional settings are new, each with the default above:
`AGENT_BUS_WORKERS`, `AGENT_BUS_TENANT_WORKERS`, `AGENT_CONVERSATIONS`, `AGENT_CONVERSATION_TURNS`,
`AGENT_CONVERSATION_BYTES`, `AGENT_CONVERSATIONS_BYTES` and `AGENT_CONVERSATION_IDLE_SECONDS`.
`git diff v0.2.0..v0.3.0 -- src` adds no other environment read.

## Known issues

Security-relevant first.

1. **Service turns write every tenant's trace to the shared pod's disk** (#38): a service turn's
   trace (the message, the answer and every tool observation) is written under `TRACE_DIR` and
   never removed.
2. **The image bundles GPL and LGPL code** (#40): it is built on `python:3.12-slim` (Debian: glibc,
   bash, coreutils, dpkg, readline), so the image is not published. It moves to `scratch` with
   static binaries before it is.
3. **Dataset-confined launch credentials are not yet confined at Lake** (lake#1055): the runtime
   refuses what it cannot prove, but the launch token itself still carries the person's reach.
4. **The bus client is not yet the workspace-aware cutover client** (#6): no `workspace_id` on
   every call, no lease renewal, no idle backoff.
5. **One test fails** (#41): `tests/test_lake_bus.py::test_a_task_is_claimed_run_and_answered_on_the_bus`
   still expects a bus turn's body without the `claim` that #33 adds. The behaviour is the intended
   one; the test was not updated with it.

## Where it has run

**The v0.3.0 tree had not run on a development environment when it was released.** Lakes take the
operator's default runtime image; moving it to `:v0.3.0` is a separate operator change.

## The image

Built from the tag `v0.3.0` with BuildKit (linux/amd64, the repository's Dockerfile), then tagged
`:v0.3.0` on that digest without rebuilding. The digest is recorded here once it is built.
